> 依据：**本系统实测**。agnes 端点无公开的官方提示词文档，本包结论全部来自
> 线上实测与事故复盘（首帧 1171 字稀释、多人物事故、断连事故等），
> **未经实测的推断一律不作依据**；方舟文档的规则不得跨端点套用到这里。

## 一、提示词结构（六要素顺序）

按「主体 → 场景/环境 → 风格 → 光照 → 构图 → 质量要求」写一段连贯中文长句：

```
<主体与动作神态>，<场景与环境细节>，<画风关键词>，<光线方向与质感>，
<景别与构图>，<质量收尾词>
```

- **中文自然句**即可，无需翻译英文 tag；**禁止逗号碎片化堆砌**（碎片 tag 会让模型逐词注意力分散，主体被稀释）。
- 负面词由节点参数单独传（`negative_prompt`），**不写进正向提示词**——正向里的否定句会被弱模型反向触发。

## 二、长度预算（硬约束，代码已执行）

| 场景 | 建议长度 | 依据 |
| --- | --- | --- |
| 角色定妆图 | 80-150 字 | 主体单纯，过长会引入无关细节 |
| 场景主图 | 60-120 字 | 焦点在环境物件 |
| 道具定妆图 | 60-120 字 | 单物件，纹理写足即可 |
| 分镜首帧（含参考图） | **≤600 字** | 超限后约束句稀释主体，画面变空洞 |

**超长是当前实测最大问题**：首帧提示词曾达 1171 字（约束样板占 63%），主体描述只占 17%——
画面细节反而变弱。`PROMPT_BUDGETS` 会记录超标并在生成参数中外露。

## 三、参考图策略

- **编号对齐**：提示词中「（参考图N）」与上送 `images` 数组**顺序严格一致**（N 从 1 起）。
- **职责声明必须写明**：图生图会把参考图内容融进画面——不声明用途时，模型会把**每张**参考图的人物都画出来（首帧多人物事故的直接成因）。正确写法：
  `角色参考图仅作对应人物的长相、发型与服装参考（控制身份，不控制姿态、构图与光线），画面内容与出场人物以文字描述为准`
- **张数上限**：端点约 5-8 张（超限会静默截断或直接断连）。**参考图越多，单图遵循度越低**——4 张以上时道具/陈设漂移明显回升，故按「角色 > 场景 > 道具」优先级裁剪，宁可少而准。
- **自动压缩**：本地图 base64 前压缩到长边 ≤1024 JPEG（质量 85）——未压缩时 5 张 PNG 约 3MB 会触发端点 `Server disconnected`（实测事故）。

## 四、易崩点与规避

| 风险 | 表现 | 规避写法 |
| --- | --- | --- |
| 多余肢体 | 三条手臂、多指 | 正文**正向**声明「人物只有两条手臂、两只手（每只手五根手指）」，末尾再复锚一次（首尾双锚）；负向词补「多余的肢体，畸形的手」 |
| 俯视大头照 | 全身照被截成半身 | 视点约束必须**具体化**：「相机与人物眼睛同高，正面平视拍摄，严禁俯视或仰视」——只写「平视」会被长 prompt 稀释 |
| 半身截断 | 未写鞋履时模型放大上半身 | 服装描述**从上到下写全**：上装、下装、鞋履缺一不可 |
| 呆滞证件照 | 表情僵硬 | **不写**「面部无表情」「均匀正面柔光」——表情气质交给人物神态描述 |
| 浮空人脸 | 空镜里出现人脸 | 场景提示词**不得出现任何含「人」的字样**（含「严禁出现人物」这类否定句——否定句里的人脸名词会成为注意力标签反向触发） |
| **幽灵文字** | 画面里渲染出提示词中的属性标注（实测地面倒影出现「22岁中国农村青年」——人物年龄/国籍锚被当成画面内文字画进地砖） | 人物属性锚（年龄/国籍/外貌括号）会被模型当**画面内文字**渲染：组装侧必须在锚句后紧跟豁免声明「括号内为设定说明而非画面内容，画面中不得出现任何文字、数字、年龄或姓名标注、地面文字」；负向词压不住，必须就近声明 |
| 姿态与正面冲突 | 侧身描述导致补画正面手臂 | 定妆图禁写姿态词（侧身/背对/转身/回眸）与机位词（仰拍/俯拍） |
| **参考图的姿态支配力** | 要求角色「背对 / 伏在垛口 / 侧身」等特殊姿态，成图**仍是正面直立**（与文字矛盾） | **姿态用取景语言写**：不写「背对镜头」，写「**画面里只见他的背影与后脑、看不见正脸**」——姿态指令等于要求模型把参考图里的人**转过去**，而参考图是正面直立照，它会保守地跟参考图走；取景语言只描述**画面里看到什么**，模型按描述摆画面即可（实测一次到位）。端点**没有参考图强度参数**可调，降权重这条路不通 |

## 五、质量词与画风

- 质量词收尾：`电影级写实风格，8K 细节，浅景深，柔和自然光` 类；**避免空泛**（「高级感」「大片感」无信息量）。
- 画风关键词写在**句首**（与「项目画风」统一质感）；**画面内容不得包含皮肤/毛孔等人物质感词**（会诱导模型生成人脸特写）。
- 文字渲染：需要画面中出现文字（招牌/信纸/写字板）时，**明确写文字内容与位置**——模型对中文长句渲染能力有限，只写关键短词（如「上面是手写的中文『雨夜』二字」）。

## 操作纪律（对 LLM 的硬约束，违反即不可用）

- **不得降级或替换模型**：用户配置了哪个模型就用哪个（含档位与端点）；不可用时报错并说明原因，**禁止自行改投其它模型或档位**——这与项目「禁止静默回退本地推理」同源：失败要看得见，不要悄悄换个差一点的。
- **组装之后不再改写**：系统组装完成的提示词（@引用解析、参考图预算裁剪均属**组装环节**，允许）到端点之间**零改写**——不追加标题/前缀/后缀/风格词/质量词，不改标点与换行。参数（画幅/时长/参考图）一律走独立字段，不写进提示词正文。
- **不使用 `--` 符号**：该符号之后的内容可能被模型截断，不会被解析或响应。

**本模型专属**：

- **I2I 输入图引用用 `[img0]`、`[img1]`**：生图阶段不得用 `@图片`／`图1` 格式（`@图片N` 只用于视频生成）。
- **保留项不得只写「保持不变」**：必须逐项列明主体身份、结构、构图、位置比例、透视、光影方向、材质、层级关系。
