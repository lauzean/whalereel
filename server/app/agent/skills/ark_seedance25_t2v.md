## 一、与 2.0 的硬差异（直接影响提示词写法）

| 维度 | Seedance 2.0 | Seedance 2.5 |
| --- | --- | --- |
| **时间戳** | 不响应，只认镜头序号 | **响应整数秒时间戳** |
| **多视图主体参考** | 不建议（易被识别为多个主体，加剧 ID 漂移） | **支持**（超 5 主体时仍建议单视图） |
| 输出宽高比 | 固定 6 档 | 由输入素材控制，支持 **[0.4, 2.5]** 任意比例 |
| 输出格式 | — | 支持 **MOV**（延长/编辑的声画一致性更好） |

**时间戳三条规则**（2.5 专属能力，用错反受其害）：
- 以「1 秒」为单位；**不建议用时间戳控制频率**（「一秒摇头 3 次」这类一律不写）；
- 时间区间必须**连续**，不得出现「0-3 秒…5-6 秒…」的断裂；
- 区间内剧情太少模型会自由发挥，太多会过度剪切或遗漏——**时长安排要合理**。

## 二、负向控制的边界（重要）

| 可负向控制 | 不可负向控制 |
| --- | --- |
| **字幕**（「不要字幕」「不额外加入对白字幕」） | **一切画面内容** |
| **音频**，且可细分维度：音效 / 背景音乐 bgm / 对白（「无 bgm，只生成环境音和动作音」） | |

**画面一律正向描述**——要「没有 X」就写「是什么」，不要写「不要什么」。否定词在
画面描述里会成为注意力标签，反而把被否定的东西拉进画面。

## 三、首尾帧的两种写法（本系统 fl2v 相关）

| 写法 | 效果 |
| --- | --- |
| 参数设 `role=first_frame` / `last_frame` | **锁定输出宽高比**，严格对齐输入首帧图（推荐） |
| 设 `role=reference_image` + 提示词写「图片1 为首帧」 | **不锁定宽高比**，效果相近但不完全匹配 |

**首尾帧画幅必须一致**——不一致时尾帧会被拉伸。提示词应写「以图片 x 至图片 x 的
顺序作为关键帧」（多张关键帧时首句即写明）。

## 四、素材上限与稳定性（官方量化边界）

| 项 | 建议 |
| --- | --- |
| 主体音视频 | **1-5 个效果较好**；6-10 需抽卡（稳定性下降） |
| 主体图 | 1-8 个较好；9-12 需抽卡 |
| 单次素材总量 | 图 ≤30 张（4K 以内）、视频 ≤10 段（总 ≤30s）、音频 ≤10 段（总 ≤30s） |

超过 5 个主体时**单视图比多视图稳定**；需要多视角就拆成多张不同视图分别输入，
不要在**一张图里放多视角**（这正是 2.0 时代 ID 漂移的成因）。

## 五、结构化分段（复杂事件的组织模板）

【生成目标】一句话说清视频类型与核心事件；【事件脚本】开始时（人物/道具/场景的
初始状态）→ 主要事件（连续动作）→ 结束时（可观察的最终状态）；【保持一致】声明
需稳定的人物身份与数量、服装、道具归属、空间方位。

参考素材逐份写职责：`@图片N 用于××的五官/服装/妆造，不采用图片背景`；
`@视频N 用于动作与运镜参考，不采用其中的人物与场景`；实际未用的素材明确声明不参与。

## 六、符号与情绪

- 台词用 `{}`（她低声说{我知道了}），非中英文台词**须标注语种**；音乐用 `()`，
  音效用 `<>`；多人对话逐镜头绑定说话人，其余人物自然闭口聆听；
- **正文里不要自造 `【】` 标记**：`【全局定义】【视频画面】` 等是**系统结构段名**
  （保留字，由系统统一书写）；官方约定中 `【】` 亦用于标记**字幕内容**
  （如 `【第一章：启程】`），正文自造 `【】` 会与结构段名撞车、语义混淆；
- 情绪控制公式：情绪方向 + 触发事件 + 可观察表现（眼神/嘴角/手部动作），
  不堆满微表情。

## 操作纪律（对 LLM 的硬约束，违反即不可用）

- **不得降级或替换模型**：用户配置了哪个模型就用哪个（含档位与端点）；不可用时报错并说明原因，**禁止自行改投其它模型或档位**——这与项目「禁止静默回退本地推理」同源：失败要看得见，不要悄悄换个差一点的。
- **组装之后不再改写**：系统组装完成的提示词（@引用解析、参考图预算裁剪均属**组装环节**，允许）到端点之间**零改写**——不追加标题/前缀/后缀/风格词/质量词，不改标点与换行。参数（画幅/时长/参考图）一律走独立字段，不写进提示词正文。
- **不使用 `--` 符号**：该符号之后的内容可能被模型截断，不会被解析或响应。

**本模型专属**：

- **不响应「用时间戳控制频率」**（如「一秒摇头 3 次」）：时间戳只用于划分事件区间，不用于控制动作频次；区间必须连续，不要断裂。
- **负向控制仅限字幕与音频**：可写「不要字幕」「无 bgm，只生成环境音和动作音」；**画面内容一律正向描述**——要「没有 X」就写「是什么」，否定词在画面描述里会成为注意力标签，反而把被否定的东西拉进画面。
