## 一、生成模式（选错模式 = 白跑一次）

方舟 Seedance 的**首帧**与**参考图**是**互斥模式**，混传返回 400「cannot be mixed」：

| 模式 | 触发 | 说明 |
| --- | --- | --- |
| **keyframe** | 传首帧（`role=first_frame`） | 首帧即实际起始画面，**保真**。提示词只写首帧之后的动态延续 |
| **reference** | 不传首帧、传参考图（`role=reference_image`） | 参考图作外观/陈设锚点，最多 4 张 |

**我们系统的选择**：ref2v 链路**恒有首帧**（视频以首帧起像）→ 走 keyframe 模式，
**参考图不参与**。因此提示词中**不要出现「（参考图N）」编号**（本端点不接收参考图，
编号会悬空指向不存在的图）。人物身份由首帧承担，而首帧本身已用角色/场景参考图生成。

**编辑/延长任务**必须直接用「视频N」指代，**不能写「参考视频N」**——后者会被模型
误判为参考任务（官方明确警告）。本系统当前不产出此类提示词，知晓即可。

## 二、画面描述结构

**基础公式**：`画面描述 + 运镜描述 + 美学描述`

**要素顺序**（官方进阶公式）：
`精准主体 + 动作细节 + 场景环境 + 光影色调 + 镜头运镜 + 视觉风格 + 画质 + 约束条件`

多阶段镜头按时间轴分段，**每段依次写**：

```
运镜方式（全景缓慢推近/固定机位/镜头切至）
  → 主体动作与神态
  → 位置或空间变化
  → 声音信息
```

- **本系统一个分镜 = 一个镜头**，【视频画面】内的**时间小节**是**镜头内的动作
  阶段**，不是镜头切换——不要写成「镜头 1：…镜头 2：…」的换镜结构；
- **时间小节的秒数是内部编排与对账锚点**（系统结构要求，用于覆盖时长校验与首帧
  派生），**不是给模型的时间指令**：官方明确「Seedance 2.0 对精确时间（如 0–3 秒）
  的支持不稳定，强行限制时长可能导致生成结果异常」——**2.0 响应镜头序号而非
  时间戳，只有 2.5 才响应整数秒时间戳**。因此正文按剧情自然分配节奏，不要写
  「第 3 秒必须转头」这类卡秒指令；
- **单镜头只指定 1 种运镜**（多运镜混写会让模型把运镜和动作搅在一起）；
- **运镜用标准术语**（推/拉/摇/移/跟/环绕/俯冲/手持晃动），模型理解力强，无需解释；
  小众专业名词才需转成 `[名词 + 描述性解释]`；
- **精简聚焦**：提炼本镜关键事件，**不得把整段剧本直接当画面描述**（官方列为
  双胞胎/理解混乱的成因之一）。

## 三、符号约定（官方硬规定，逐条遵守）

提示词里的符号有**固定语义**，用错会让模型把信息归错类：

| 信息类型 | 符号 | 示例 |
| --- | --- | --- |
| 音乐 | `（）` | （背景中播放着快节奏的摇滚乐） |
| 音效 | `<>` | <远处传来狗叫声> |
| 台词 | `{}` | {你好，世界}；小语种须标语种：用日语说道{こんにちは} |
| 字幕 | `【】` | 【第一章：启程】 |

- **台词语言必须统一**，避免中英文混用（专有名词除外）；
- 台词**不重复原句+语气**以外的东西；说话人绑定要逐句写明。

## 四、动作与情绪的写法（本模型的核心弱点）

Seedance 对**动作幅度**敏感，越大越容易崩：

| 可拍（优先） | 必崩（规避） | 替代拍法 |
| --- | --- | --- |
| 缓慢抬手、微微低头、用力蹬地 | 狂奔、大跳、翻滚 | 拆「起势/落定」两小节，中段留白 |
| 连贯的小幅度动作 | 复杂肢体交错（拥抱/扭打） | 切反应镜或拍剪影 |
| 转身、递物、坐下 | 抛接/抛物 | 只拍结果态（东西已在桌上） |

**四条写法要点**：
- **肢体细化 + 程度量化**：具体到手/腿/头/肩背部位，并写幅度速度力度（缓慢/微微/用力）；
  避免「快速」「猛地」；
- **动作承接**：写明惯性延续（「借着转身的惯性顺势抬手」），衔接才自然；
- **情绪外化**：禁抽象情绪词，一律写身体细节——

| 抽象情绪 | 外化为动作与细节 |
| --- | --- |
| 悲伤 | 低头、肩膀微微颤抖、眼眶泛红、手指无意识地攥紧衣角 |
| 喜悦 | 嘴角抑制不住地上扬、眉眼舒展、脚步变得轻快 |
| 紧张/焦虑 | 频繁地看手表、手指不停敲击桌面、呼吸急促、眼神闪躲 |
| 愤怒 | 双拳紧握、下颌线紧绷、胸口剧烈起伏、从牙缝里挤出话语 |
| 释然 | 长长地舒了一口气、紧绷的肩膀完全放松、露出淡淡的微笑 |

- **概括优先**：动作优先用概括性描述（「连续做了几组高抬腿」），只在少数有记忆点
  的动作上写具体细节，**不建议重复写相同动作**；表情写描述性语句、少用成语
  （「津津有味地吃饭」→「脸上带着满足的笑容，大口地吃饭」）。

## 五、主体定义与素材职责

**明确的主体定义是防 ID 漂移的第一道闸**：

- 推荐句式：`将<图片N>中的[主体核心特征]定义为<主体N>`——核心特征用 **2–3 个清晰
  稳定的静态特征**（服饰/发型/外观/类别），确保唯一可识别；
- 多素材指向同一主体时统一绑定；多主体分别定义并**全程沿用同一标签**
  （「警察」「小偷」而不是「高个子男人」「矮个子男人」），避免指代混乱；
- 未定义主体的简单场景，每次提及都写 `<主体N>@<图片N>` 强调绑定关系。

**素材的四种功能角色**（官方推荐配置，总计 4-5 个）：

| 角色 | 用途 |
| --- | --- |
| 角色锚定 | 锁定角色外观 |
| 场景定调 | 锁定环境与风格 |
| 运镜参考 | 锁定镜头语言与动作节奏 |
| 节奏氛围 | 用音频控制情绪、音色 |

- **不建议用满素材上限**——素材过多会让模型难以判断特征优先级，出现风格冲突、
  主体识别模糊；
- **重要素材前置**：越需要精准参考的素材，在提示词中越靠前；
- **参考素材已足够精准时只做「指代」、减少画面复述**（写「严格参考视频1 的动作与
  运镜，顺序一致」即可，不必再把动作逐帧描述一遍）。

## 六、长度预算

| 项 | 预算 |
| --- | --- |
| 画面描述主体 | 前四段合计 **250-450 字**（10 秒以上长镜 ≥350 字） |
| 声音设计 | 20-60 字 |
| **合计** | **≤900 字** |

**密度不足 → 画面空洞；超长 → 关键约束被稀释**（实测均值 1027 字偏长）。密度靠
"信息"而非"字数"堆——写具体物件与光影，不写形容词。

## 七、约束词收尾（本模型推荐）

末尾固定补约束句：`高清，细节丰富，电影质感，色彩自然，光影柔和；保持无字幕，
不要生成水印，不要生成 Logo`

—— 与系统已有的「不生成字幕、标题、水印、拼贴、分屏或额外人物」合并使用，
避免重复堆叠。

## 八、易崩点与规避

| 风险 | 表现 | 规避 |
| --- | --- | --- |
| **人物 ID 漂移** | 中途换脸、撞脸明星被审核拦截 | ①人脸参考图**独立且权重足**（人脸区域占比过小的混用图无效）；②写`<主体1>的面部特征参考图片1（大头照），妆造参考图片2（全身照）`；③**重要素材前置**；④**不用多视图**（同一人物多角度会被识别成多个主体，反而加剧漂移） |
| **双胞胎 / 人物复刻** | 同框出现两个完全相同的人 | 逐人定义+参考图对应关系（`张三（对应图片1）`）；末尾加全局约束「视频全程禁止出现外形、着装、配饰完全一致的人物，禁止生成同款分身、双胞胎效果」；人物参考用**单人独立照片** |
| **参考人物过多** | 超过 4 人时人数不符（少人/多人） | 分组生成图片（每组 ≤4 人）再图生视频；同框镜头优先拆解 |
| **风格漂移** | 期望 2D/3D 动漫，出真人写实 | 提示词必须有明确风格约束词；更精准的做法是**把参考图先转成目标风格**再生视频 |
| **字幕** | 未要求却在画面上出现字幕 | ①约束「保持无字幕」「避免生成任何文字或字幕」；②**竖屏出字幕概率明显高于横屏**（本系统以竖屏为主，此项必须显式写）；③参考图里非必要的文字先用图片编辑能力去掉；④**官方明说无法 100% 避免**，只能提高抽卡成功率 |
| **Logo / 水印** | 出现其他平台 Logo 水印 | 显式写「不要生成水印」「不要生成 Logo」 |
| **内容安全误杀** | 写实 AI 人脸首帧被判「疑似真人」（PrivacyInformation）→ **视频任务全数失败** | **立项即定画风**：实测写实风格 **8/8 全拦**（不是抽卡问题），动漫人脸放行；真人短剧在本端点走不通，需二次元/3D 等非写实画风或换非火山系端点。画风是**项目级属性、中途改不了**——改画风要重建项目重跑（资产与首帧全部重做） |
| **流体/碰撞** | 倒水/摔倒演成喷涌/穿模 | 只拍结果态，过程靠声音与反应镜 |
| **文字画面** | 招牌/信纸文字乱绘 | 写「上面是手写的中文『X』」限定内容；官方建议**优先用常用字**，避免生僻字与特殊符号；精度要求高时后期补 |
| **长镜动作过载** | 十几秒塞多个事件 | 一个片段一个可见节拍 |
| **中文发音不准** | 多音字/生僻字/形近字读错 | 台词里的易读错字换成**发音一致的常用同音字**（如「螭龙山」→「吃龙山」）；非中英文台词须标注语种 |
| **音色不符** | 参考音频音色与实际偏差 | 在台词处补充**音色特征描述**（如「低厚温润带细碎颗粒感的中年男声」），并让台词语气与参考音频风格相近 |

## 九、参数与端点

- 时长钳位 **[5, 12] 秒**（实测 seedance-2-0-mini 不支持 <5s）；
- 分辨率以文本后缀注入：`--resolution 1080p/720p/480p --duration N --watermark false`；
- 首帧/参考图以 base64 data URL 上送（本地图需转换）；
- **seed 不支持**：方舟端点静默忽略 seed 参数（同 seed 两次出图不同，实测），
  系统不下发；「固定种子重试」在本端点不可用。

## 操作纪律（对 LLM 的硬约束，违反即不可用）

- **不得降级或替换模型**：用户配置了哪个模型就用哪个（含档位与端点）；不可用时报错并说明原因，**禁止自行改投其它模型或档位**——这与项目「禁止静默回退本地推理」同源：失败要看得见，不要悄悄换个差一点的。
- **组装之后不再改写**：系统组装完成的提示词（@引用解析、参考图预算裁剪均属**组装环节**，允许）到端点之间**零改写**——不追加标题/前缀/后缀/风格词/质量词，不改标点与换行。参数（画幅/时长/参考图）一律走独立字段，不写进提示词正文。
- **不使用 `--` 符号**：该符号之后的内容可能被模型截断，不会被解析或响应。

**本模型专属**：

- **不响应时间戳**：只认镜头序号，不要用「0-3 秒」这类精确锚点组织画面（写了也会被剥离）。
- **负向控制仅限字幕与音频**：画面内容一律正向描述（要「没有 X」就写「是什么」）。
