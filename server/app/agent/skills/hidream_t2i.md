## 一、提示词结构

**单段连贯长句**（80-150 字），顺序：

```
主体 → 动作神态 → 服装材质 → 光影氛围 → 画质词
```

- HiDream-O1 理解自然语言长句，**禁止逗号碎片化 tag 堆砌**；
- 质量词后置收尾：`……，电影级打光，8K 细节，写实皮肤质感`；
- 中文输入即可，无需英文 tag；负面词由 `negative_prompt` 参数单独传。

## 二、本模型偏好（善用）

- **完整场景叙述**：把镜头关系写进句子（「远景中她站在城门下，前景是残破的石狮」），而非堆叠景别关键词；
- **光源方向具体化**：本模型对面部特写的光源极敏感——「侧逆光」「顶光」「烛光从左下方打亮」远优于泛写「光影氛围」；
- **画风词前置一次即可**：以「项目画风」开头写进首句，无需重复强调。

## 三、负面词（本模型支持，务必使用）

本地管线走 `negative_prompt` 参数，推荐按形象类型取用（与系统内置三套一致）：

| 类型 | 负面词 |
| --- | --- |
| 角色基础形象 | 多余的肢体，三只手，四只手，多只手臂，多余的手指，畸形的手，肢体扭曲，手持物品，手持武器，画面重影，多个人物 |
| 妆造形象 | 多余的肢体（同上肢体块），画面重影，多个人物（**不禁手持**——妆造可含持械造型） |
| 四视图 | 肢体块，手持物品，手持武器，画面重影，人物残缺，格间人物粘连（**禁"多个人物"**——会抑制一行四列布局） |

## 四、性能与运行注意

- **本地推理耗时长**（CPU 可达每张数小时）——**仅在远端端点不可用且确有 GPU 时才回退本地**；
- 权重体积大（约 66G），首次加载耗时长（有加载进度泵）；
- 失败时不要静默回退：本地路径失败会显著拖长任务，错误应透出（系统已有 `_local_fallback_ok` 守门：权重未装不回退）。

## 五、易崩点与规避

| 风险 | 规避 |
| --- | --- |
| 姿态与正面约束冲突 | 定妆图禁写姿态词（侧身/背对/转身/回眸）与机位词 |
| 半身截断 | 服装从上到下写全（上装/下装/鞋履） |
| 呆滞证件照 | 不写「面部无表情」「均匀正面柔光」——表情气质交给神态描述 |
| 长 prompt 被稀释 | 保持 80-150 字，超长同样会稀释主体（与云端模型同理） |

## 操作纪律（对 LLM 的硬约束，违反即不可用）

- **不得降级或替换模型**：用户配置了哪个模型就用哪个（含档位与端点）；不可用时报错并说明原因，**禁止自行改投其它模型或档位**——这与项目「禁止静默回退本地推理」同源：失败要看得见，不要悄悄换个差一点的。
- **组装之后不再改写**：系统组装完成的提示词（@引用解析、参考图预算裁剪均属**组装环节**，允许）到端点之间**零改写**——不追加标题/前缀/后缀/风格词/质量词，不改标点与换行。参数（画幅/时长/参考图）一律走独立字段，不写进提示词正文。
- **不使用 `--` 符号**：该符号之后的内容可能被模型截断，不会被解析或响应。

**本模型专属**：

- **I2I 输入图引用用 `[img0]`、`[img1]`**：生图阶段不得用 `@图片`／`图1` 格式。
- **保留项不得只写「保持不变」**：必须逐项列明需要保留的要素。
